# Reviewer Checklist

Используй этот чек-лист как независимую проверку для глубоких отчетов перед финальной выдачей. Проверяющий агент должен искать ошибки, а не улучшать стиль ради красоты.

## 1. Scope и ограничения

- Указаны дата анализа, сектор, тип объекта анализа, география, основной горизонт и глубина анализа.
- Есть разделение выводов по горизонтам, если кратко-, средне- и долгосрочные выводы отличаются.
- Четко написано, что включено и исключено.
- Missing data не скрыты и не заменены предположениями.

## 2. Evidence table, факты и источники

- Перед интерпретацией есть evidence table с метрикой, Tier, значением, периодом наблюдения, датой публикации, датой доступа, источником, свежестью и надежностью.
- Ключевые факты подтверждены источниками с датами.
- Market size и growth не держатся на одном слабом источнике, если вывод сформулирован уверенно.
- Новости используются для катализаторов, а не как единственная основа инвестиционного тезиса.
- Старые данные явно помечены как stale / potentially stale и не подаются как свежий факт.

## 3. Факт / Интерпретация / Допущение

- Факты отделены от интерпретаций.
- Допущения помечены как допущения и имеют метрики проверки.
- Нет выдуманных цифр, источников, ссылок, дат, событий, цитат или чрезмерно точных прогнозов.

## 4. Tier discipline

- Есть Tier 1 / Tier 2 / Tier 3 метрики.
- Tier 1 напрямую влияет на итоговый вывод.
- Tier 2 проверяет или уточняет Tier 1.
- Tier 3 используется только как контекст и не перевешивает Tier 1.
- Если сильный вывод держится на Tier 3, confidence снижен и вывод помечен как гипотеза / допущение.

## 5. Инвестиционная логика

- Есть причинная цепочка `драйвер → profit pool → компания / подсектор → оценка → риск → инвестиционное действие`.
- Показано, кто выигрывает, кто проигрывает и почему.
- Рекомендованные направления ранжированы, а не просто перечислены.

## 6. Valuation discipline

- Оценка связана с ростом, маржей, ROIC, капитализацией, циклом и рисками.
- Нет вывода «дешево / дорого» только на основе одного мультипликатора.
- Указано, какой сценарий уже может быть заложен в цену.

## 7. Anti-thesis, counterargument и риски

- Anti-thesis реально атакует главный тезис.
- Есть counterargument, который может изменить вывод.
- Риски приоритизированы по вероятности и влиянию.
- Есть условия и метрики, при которых тезис ломается.

## 8. Confidence level

- Есть уровень уверенности: высокая / средняя / низкая.
- Причина confidence связана с качеством источников, свежестью и Tier-метриками.
- Высокая уверенность не используется, если свежесть не проверена, данные stale или тезис держится на одном слабом источнике.

## 9. Формат и завершение

- Сохранена структура отчета из `templates/sector-analysis-template.md`.
- Итоговый инвестиционный вывод состоит ровно из 8 предложений.
- Есть 3–5 monitoring metrics.
- Каждый крупный блок содержит мини-вывод «Что это значит для решения?».

## Pass / Fail

Отчет проходит reviewer-check только если нет критических провалов по источникам, hallucination risk, freshness, Tier discipline, valuation, confidence, anti-thesis и итоговому формату. Если хотя бы один критический провал найден, отчет нужно исправить до выдачи пользователю.
## Mode-specific validation

Перед pass/fail проверь, что отчет валидируется по выбранному режиму из `configs/report_contract.yaml`:

- `deep` требует полный 18-секционный отчет;
- `standard` требует компактный отчет с evidence table, source table, confidence, anti-thesis и 3–5 monitoring metrics;
- `short` не требует 18 секций, но должен сохранять sources, freshness, confidence и ограничения данных.

Короткий режим не должен падать только потому, что в нем нет 18 deep-секций; deep режим не должен проходить по short-контракту.
