# Parsing Policy

Парсинг в этом агенте — это извлечение инвестиционно важных данных из сайтов, PDF, отчетов компаний, презентаций, таблиц и новостей.

Цель парсинга — не собрать максимум текста, а получить проверяемые `evidence items`, которые поддерживают выводы отчета и соответствуют `configs/report_contract.yaml`.

## Что парсить

Парсить только данные, которые влияют на:

- размер рынка;
- CAGR / прогноз роста;
- TAM / SAM / SOM;
- сегменты рынка;
- цены, объемы, capacity, utilization;
- маржу, ROIC, CapEx, FCF;
- market share;
- valuation multiples;
- guidance и earnings revisions;
- катализаторы и риски.

Не парсить длинные описательные абзацы, если они не дают данных или причинно-следственного вывода.

## Canonical evidence schema

Каждый извлеченный факт должен сохраняться мысленно или в `data/extracted/` в такой структуре:

```json
{
  "metric": "market CAGR",
  "tier": "Tier 1",
  "value": "8%",
  "unit": "%",
  "observation_period": "2025-2030",
  "observation_date": "2026-05-01 or unknown",
  "publication_date": "2026-05-15 or unknown",
  "access_date": "2026-06-12",
  "source_name": "McKinsey",
  "source_url": "https://...",
  "source_type": "industry_report",
  "freshness": "fresh/stale/potentially stale/unknown",
  "reliability": "high/medium/low",
  "claim_type": "fact/interpretation/assumption",
  "quote_or_evidence": "short excerpt only if needed",
  "limitations": "methodology not fully disclosed"
}
```

## Поля, которые нельзя терять

- `tier` — Tier 1 / Tier 2 / Tier 3 по весу для инвестиционного вывода.
- `observation_date` или `observation_period` — когда наблюдались данные.
- `publication_date` — когда источник опубликован.
- `access_date` — когда агент получил доступ к источнику.
- `freshness` — fresh / stale / potentially stale / unknown.
- `reliability` — high / medium / low.
- `claim_type` — fact / interpretation / assumption.

## Правила извлечения

- Всегда сохранять URL и дату публикации, если доступна.
- Если дата публикации неизвестна, пометить `publication_date: unknown`.
- Если дата наблюдения неизвестна, пометить `observation_date: unknown` и снизить confidence.
- Если источник дает только headline без методологии, надежность не выше `medium`.
- Если данные платного отчета видны только в пресс-релизе, надежность обычно `low/medium`.
- Для market size и CAGR искать минимум два независимых источника, если возможно.
- Если оценки расходятся, показывать диапазон и объяснять влияние на confidence.
- Не выдавать извлеченный текст как точную цитату длиннее разрешенного лимита; лучше пересказывать.
- Не подменять глобальный рынок региональным и наоборот.

## Как использовать parsed data в отчете

В отчете данные должны попадать в таблицу:

| Метрика | Tier | Значение | Период наблюдения | Дата публикации | Дата доступа | Источник | Свежесть | Надежность |
|---|---|---:|---|---|---|---|---|---|

А в выводах агент должен ссылаться на данные так:

```text
Факт: два источника оценивают рост рынка в диапазоне X–Y% CAGR.
Интерпретация: рынок растет структурно, но оценки TAM могут быть завышены.
Допущение: лучший profit pool может быть у поставщиков инфраструктуры, а не у операторов.
```

## Когда не парсить

Не парсить источник, если:

- он не относится к выбранной географии или сектору;
- нет даты и нельзя понять актуальность;
- он является SEO-страницей без методологии;
- он повторяет данные другого источника без добавления новой информации;
- информация не влияет на инвестиционный вывод.
