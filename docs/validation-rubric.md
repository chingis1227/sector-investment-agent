# Validation Rubric

Оцени итоговый отчет по 5-балльной шкале. Проверяй не стиль, а инвестиционную полезность, проверяемость и защиту от галлюцинаций.

## 1. Decision usefulness

- 5: отчет прямо помогает принять исследовательское решение: изучать, выражать тезис, ждать или пропустить.
- 3: много полезных фактов, но слабый вывод.
- 1: обзор без инвестиционного решения.

## 2. Evidence quality and freshness

- 5: ключевые данные подтверждены первичными / официальными и независимыми источниками; указаны даты наблюдения, публикации, доступа и свежесть.
- 3: есть источники, но часть выводов держится на вторичных оценках, свежесть неполная или есть конфликтующие данные.
- 1: источники слабые, не указаны, без дат или используются как подтверждение сильного вывода несмотря на stale / unknown freshness.

## 3. Pareto focus and Tier discipline

- 5: есть Tier 1 / Tier 2 / Tier 3 метрики; вывод строится на Tier 1, Tier 2 используется для проверки, Tier 3 не доминирует.
- 3: метрики есть, но вес данных объяснен неполно.
- 1: одна второстепенная метрика или новости подаются как полный анализ.

## 4. Causal logic

- 5: ясно показана цепочка `драйвер → profit pool → компания / подсектор → оценка → риск → инвестиционное действие`.
- 3: логика частично присутствует.
- 1: список фактов и тикеров без причинности.

## 5. Horizon and object clarity

- 5: указан тип объекта анализа, география, основной горизонт и различия между 1–3 месяцами, 3–12 месяцами и 1–5 годами, если они важны.
- 3: scope указан, но horizon split слабый.
- 1: объект, география или горизонт неясны.

## 6. Valuation discipline

- 5: оценка связана с качеством, циклом, ROIC, ростом, ожиданиями и свежими рыночными данными.
- 3: мультипликаторы есть, но вывод слабый.
- 1: «дешево / дорого» только по одному мультипликатору.

## 7. Risk, anti-thesis and confidence

- 5: сильный counterargument реально атакует основной тезис; есть условия, которые ломают вывод; confidence level обоснован источниками, свежестью и Tier-метриками.
- 3: риски перечислены, но confidence или условия поломки тезиса раскрыты неполно.
- 1: формальный список рисков без anti-thesis или уверенный вывод при слабых данных.

## 8. Fact / Interpretation / Assumption split

- 5: важные утверждения разделены на факт, интерпретацию и допущение; нет выдуманных цифр, источников, ссылок, дат, событий или чрезмерно точных прогнозов.
- 3: разделение есть, но применяется непоследовательно.
- 1: факты и мнения смешаны, ограничения скрыты.

## Pass / fail

Отчет проходит, если:

- средняя оценка ≥ 4;
- нет блока ниже 3;
- итоговый вывод состоит ровно из 8 предложений;
- есть источники для размера рынка;
- есть evidence table с Tier, датами, свежестью и надежностью;
- есть 3–5 метрик мониторинга;
- есть confidence level;
- сильный вывод не основан только на Tier 3;
- нет hallucination red flags: выдуманных цифр, ссылок, дат, источников, событий или цитат.
## Mode-specific validation

Перед pass/fail проверь, что отчет валидируется по выбранному режиму из `configs/report_contract.yaml`:

- `deep` требует полный 18-секционный отчет;
- `standard` требует компактный отчет с evidence table, source table, confidence, anti-thesis и 3–5 monitoring metrics;
- `short` не требует 18 секций, но должен сохранять sources, freshness, confidence и ограничения данных.

Короткий режим не должен падать только потому, что в нем нет 18 deep-секций; deep режим не должен проходить по short-контракту.
